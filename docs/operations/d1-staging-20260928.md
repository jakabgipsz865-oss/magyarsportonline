## Reproducible conversion

`packages/db/d1/generate_schema.py` generates the constrained 28-table D1
schema in `0001_initial.sql` from the reviewed PostgreSQL schema and the two
remediation migrations. Regeneration matched the committed SQL SHA-256:
`6e9a61ed24b16074935adbfbb837cdc06f81dbb41a825addd0a93f63b34d562f`.

`export_import.py` emits a Wrangler import file with parent tables first.
It restores the nullable `categories.parent_id` and
`stories.current_version_id` references after all rows have been inserted.
This is required because the remote importer may split the file across
transactions; `PRAGMA defer_foreign_keys=ON` alone failed remotely and D1
rolled that first trial back to the empty database. The ordered import passed
local statement-by-statement foreign-key enforcement and the remote import.

## Cutover gates still open

This snapshot is stale: live Neon had 3,336 `raw_articles` at
2026-09-27 ~22:09 UTC, while the snapshot contains 3,290. The live check
found zero non-NULL embeddings in those 3,336 records, but this must be
rechecked with the final synchronized snapshot. The 28-table D1 schema and
data parity do **not** make the current Drizzle PostgreSQL repository layer
D1-compatible. The web and Facebook publisher still use Hyperdrive/Neon.
Separate D1 adapters for the existing pipeline job and social post contracts
now pass local SQLite claim, fencing, retry, and duplicate-intent tests. They
are not yet wired to the Workers and have not been tested as a complete D1
application path.

Before cutover: port every production read/write path and atomic claim and
idempotency operation to D1, run functional regression tests against a D1
binding, take a fresh consistent Neon snapshot or proven delta, compare all
logical rows, freeze old writers, apply the final delta, validate, and deploy
compatible web/scheduler/publisher versions. Preserve Neon and record any
post-cutover writes for a tested rollback.

Cloudflare's Workers Free plan allows 100,000 D1 rows written per day,
resetting at 00:00 UTC. The remote trial used 77,060 writes, including index
updates. Do not start a second full same-day import near this quota or claim
the cutover is safe based on the historical snapshot.
