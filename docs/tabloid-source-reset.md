# Tabloid sources and remote image URLs

`DIRECT_GOSSIP` uses the publisher's gossip vertical as its positive editorial signal. Football relevance and all hard exclusions still apply. `BROAD_TABLOID_FOOTBALL` also requires a positive human-angle match. Direct feeds are polled first. No classifier or new LLM stage is introduced.

`apps/web/lib/tabloid-source-catalog.json` records every requested CORE, SECONDARY, PREFLIGHT, HOLD and RETIRED candidate. `tabloid-sources.json` contains only locally preflighted CORE/SECONDARY candidates. HOLD/PREFLIGHT sources remain unconfigured even when their RSS passes. The fixed-catalog authenticated GET `/api/internal/tabloid-source-preflight` performs the same read-only check from production; language subsets bound request duration. Failed/stale/blocked feeds are skipped. The paused `reset-sources` action deactivates previous tabloid sources and registers the selected passing subset, still inactive. It cannot run while auto-publish is enabled.

Publisher discovery evidence: [OKDIARIO's native RSS directory](https://okdiario.com/feeds/), [Virgilio's native RSS directory](https://sport.virgilio.it/feed-rss/), [Express RSS directory](https://www.express.co.uk/rss), and the RSS alternate link in [Krone Fussball](https://www.krone.at/fussball). Metro Oddballs is empty; OKDIARIO Paparazzi has no dated item in the 48-hour freshness window. These are not replaced with scraped or synthetic feeds. Blick returned HTTP 403 with the production RSS adapter during local preflight, so it is excluded; no access bypass is attempted.

RSS parsing retains every media:content, media:thumbnail and enclosure candidate, including declared type and dimensions. Known 1200px+ images outrank 800px+ images. Small/dimensionless RSS candidates produce a placeholder or optional accepted-article HTML metadata lookup. Metadata selection reads OG, Twitter and Article JSON-LD; unknown metadata dimensions are explicitly reported as unknown. Small duplicate URLs cannot escape their size declaration through another metadata tag. HTML requests have a four-second timeout and two-megabyte limit; blocked, redirected, paywalled or non-HTML responses are skipped. Image files are never requested, resized, cached or rehosted. The selected absolute publisher URL is stored unchanged. MediaThumb continues to use a plain remote img.

Rejected RSS items retain their raw-article persistence path without a Writer job. They never trigger the optional HTML request. The source reset touches only Source configuration; no schema migration or canonical article deletion occurs.

Validation covers both source modes, all required image selection cases with real XML parsing, exact URL persistence, rejected-item queue isolation, HTML-only fetching and paused authenticated source reset. Publication and corporate cron must remain OFF after deployment. Use the production preflight report to review up to five accepted/rejected titles per source and ten image metadata samples. No article generation is part of this rollout.
